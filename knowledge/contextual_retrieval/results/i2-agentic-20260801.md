# I2 Agentic Contextual Retrieval Engineering Result — 2026-08-01

## Decision

The tested contextual index did not meet the registered adoption gate. Under
this dense-only, BGE-M3, MultiHop-RAG, vector top-4 configuration, Contextual
Retrieval should remain opt-in rather than become the default indexing strategy.

This is an engineering decision from one disclosed evaluation, not a claim that
Contextual Retrieval is generally ineffective. The result does not cover
contextual BM25, reranking, other context prompts or models, other corpora, or
other retrieval configurations.

## Evaluation scope

The paired A/B changed only the text embedded at index time:

```text
Baseline:    BaseEmbeddingText
Contextual:  DeepSeek-V3.2 Context + delimiter + BaseEmbeddingText
```

Both lanes used the same 450-case panel, 13,086 chunks, BGE-M3 embeddings,
PGVector vector search, top-4 retrieval, DeepSeek-V3.2 Agent, prompt, tool
contract, and `query-guard/v1`. Both returned the same original chunk content
and metadata to the Agent. Context generation and the two indexes were frozen
before the Agent and Judge phases and were not rebuilt between repeats.

The formal schedule contained 450 cases, two lanes, and three logical repeats:

```text
question types:          comparison / inference / temporal, 150 each
Agent executions:        450 x 2 x 3 = 2,700
Judge metrics:           7
logical metric cells:    2,700 x 7 = 18,900
paired cases:            450
```

The repeats reused one frozen panel, Context cache, pair of indexes, and
configuration. They are repeated executions, not three independent datasets or
three independently rebuilt experiments. Agent trajectories and external model
calls can still vary, so the result is treated as production-like engineering
evidence rather than a noise-free causal estimate.

The frozen formal Judge profile was:

```text
Judge model:             GLM-5.2
temperature:             0
reasoning parameter:     omitted
max_tokens:              65,536
workers:                 8
batch size:              25
record attempts:         5
bootstrap resamples:     10,000
bootstrap seed:          20260725
```

The paired bootstrap first averages the three executions of each case and lane,
then resamples the 450 case-level pairs while stratifying by question type. It
does not treat the 1,350 executions per lane as independent cases.

## Question-type and mechanism diagnostics

- Comparison questions were directionally better overall, but most intervals
  crossed zero.
- Inference Context Precision regressed by `-0.0429`, with a paired 95% CI of
  `[-0.0725, -0.0128]`.
- Temporal questions were mildly positive overall, but not enough to establish
  a stable aggregate improvement.
- Average cumulative evidence recall changed from `0.4744` to `0.4695`.
- Average search calls changed from `2.9393` to `2.9407`.

The almost unchanged search count and slightly lower cumulative evidence recall
do not support a mechanism in which contextual indexing reduced search effort
or consistently exposed more registered evidence in this configuration.

## Registered gate

| Check | Requirement | Observed | Result |
|---|---:|---:|---:|
| Answer Correctness delta | `>= +0.02` | `+0.0036` | Fail |
| Answer Correctness 95% CI lower bound | `> 0` | `-0.0111` | Fail |
| Context Precision delta | `>= -0.01` | `-0.0057` | Pass |
| Agent failure-rate delta | `<= +1pp` | `-0.37pp` | Pass |

The gate decision was `method_not_effective`: the tested method did not earn
default adoption under the registered engineering criteria.

## Persistent Judge fallback audit

The historical machine-readable bundle reported `134` recovered records and no
final Judge error because its server revision converted the last unavailable
metric in three records to numeric zero. A later audit separated actual recovery
from persistent missingness:

```text
true record-level recoveries:       131
persistent missing-metric records:    3
artifact-reported recovered:         134
extra record retry attempts:         158
```

The three persistent cells were all in the Baseline inference slice:

- two Answer Relevancy cells remained unavailable after five record attempts
  because the Judge RPC or generation did not complete;
- one Faithfulness cell remained non-finite after five attempts. Metric-semantic
  missingness is the most likely explanation, but the intermediate statement
  extraction was not persisted, so that cause is not claimed as proven.

These are `3` unavailable cells out of `18,900` logical metric cells. They are
not interpreted as method scores of zero. The original artifacts are preserved
as historical evidence; the implementation in this PR instead fails closed and
keeps an exhausted missing or non-finite metric as a Judge error.

Consequently, the run is usable as disclosed engineering evidence but is not
presented as strictly complete Judge evidence under the current fail-closed
policy. In particular, the historical artifact's successful status must not be
read as proof that every Judge metric completed without fallback.

decision does not change.

## Limitations

- The three repeats share one panel, Context cache, and pair of indexes; they
  are not independent dataset replications.
- Production-like Agent trajectories and external model services introduce
  noise that frozen configuration and paired scheduling cannot eliminate.
- Three persistent Judge metric cells were not replayed and are disclosed with
  complete-case sensitivity instead.
- The experiment covers dense vector retrieval with one context generator,
  prompt, embedding model, corpus, chunking configuration, and top-k value.
- The report contains only aggregate evidence. Raw questions, answers, Context,
  per-record scores, model transcripts, databases, logs, credentials, endpoints,
  and machine-specific paths are intentionally excluded.
